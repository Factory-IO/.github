## Four Beats

1. **Name the scene.** Give the Factory I/O session a short title before you edit the 3D factory scene.
2. **Pin the live sensors.** Keep current conveyors and the owned controller on the Factory I/O board and leave unused parts aside.
3. **Check the PLC link.** Read the Factory I/O summary of the PLC connection before you treat a layout as ready.
4. **Close the loop.** Note which scenes are ready so the next Factory I/O visit does not start by hunting the conveyor layout.

## First Questions

**Does Factory I/O replace the controller the lab already owns?**  
No. Factory I/O sits beside the PLC and the scene you already run on a controller the reader owns.

**Can two students share one computer?**  
Yes. Each person keeps a separate Factory I/O profile for their own lab scene.

**Will Factory I/O stay workable on an older lab laptop?**  
Yes. Factory I/O is meant to stay light during a normal lab exercise.

**What should a new user try first?**  
One small Factory I/O 3D factory scene today tied to a controller you own, then the same industrial scene again tomorrow.

## Field Note

Factory I/O is easier to trust when the scene stays smaller than the plant it came from. A named session shows which lab is active, the pins show which sensors you will watch today, and the closing note tells the next person which PLC connection drives the conveyor layout. That record is short on purpose: not a copy of every motor, only the path back to the industrial scene and the controller the reader owns.

The same loop fits a student conveyor, a client packing cell, or a computer shared by two labs. Open the last Factory I/O session, confirm one 3D factory scene, and leave the industrial scene easier to follow than you found it. Other programs stay where they are. Factory I/O only holds the scene, the PLC connection, and the handoff.

## One Real Pass

Pick a lab exercise that already has a name and a controller you own: a short conveyor, a sorting cell, or a packing line on the lab desk. Open it in Factory I/O, keep only that scene on the board, and read one PLC connection you can point to. A pass is done when that link stays tied to the 3D factory scene and the unused parts are no longer in the way. Factory I/O does not need a full rebuild of the plant before it is useful.

If the pass feels crowded, the scene is too wide. Drop anything that belongs to a different exercise and leave it out of this workspace. The next pass can have its own title. What matters is that this one stays readable from the first sensor to the last conveyor, with the summary still matching the industrial scene on that lab desk.
